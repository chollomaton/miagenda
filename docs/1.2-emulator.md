# Mi Agenda 1.2 — isolated Firestore/Auth integration

This configuration is exclusively for a fictitious `demo-miagenda-mirror`
project. It contains no real Firebase credentials, `.firebaserc`, deploy targets,
Functions deployment or production rules changes. `firestore.rules` in the web
root remains unchanged. Only `emulator/firestore.rules` is loaded by the runner.

## Requirements and operation

Node 24, Java 21+, and `npm ci --prefix emulator`. Dependencies are pinned in a
separate lockfile. Java can be a locally extracted Temurin JDK; prepend its
`Contents/Home/bin` to PATH. No global installation, Firebase login, billing or
real project is required. Chrome is used from its normal macOS application path
in headless mode with a new, temporary browser context.

From the web root:

```
bash scripts/run-mirror-emulator.sh start
# Stop with Ctrl-C; this block neither imports nor exports emulator data.
bash scripts/run-mirror-emulator.sh tests
bash scripts/run-mirror-emulator.sh e2e /absolute/path/to/isolated/native/repo
```

`tests` starts/stops Firestore and Auth and runs rules, authority and authority
TypeScript checks. `e2e` additionally starts/stops the local authority and Vite,
builds the Swift Package and repeats the browser E2E twice. Ports must be free:
Firestore 18080, Auth 19099, authority 18081, Vite 15173, hub 14400, logging 14500,
Firestore websocket 9150. All bind to loopback. The E2E deliberately clears only
Firestore for this fixed demo project at each repetition. Never run it against a
shared emulator with data you need. Synthetic receipts/screenshots go to ignored
`work/emulator-e2e/`; the browser profile is discarded. Auth accounts remain only
in emulator memory until shutdown.

## Authority and rules boundary

The authenticated owner reads mirror state/content and retains exclusive access
to editable `/users/{uid}/entities`. Owners cannot write mirror content. An active
publisher can stage immutable envelopes `{publisherID,payload}` only under its
assigned owner, with a live lease and current grant ID. Neither publisher nor
owner can directly activate state. Hash/reference validation and pointer CAS
belong to the local authority, because Firestore rules cannot recursively hash an
arbitrary content graph. The same envelope and Firestore reader work in normal
runtime; existing raw wire documents remain readable for compatibility.

Challenges use 32 cryptographically random bytes; only the SHA-256 digest is
stored. Scope, owner, publisher, expiry, claim and consumption live in Firestore.
Owner claim and owner confirmation are separate authenticated operations; confirm
atomically consumes the challenge and replaces the single owner grant. Replay,
wrong owner, expired challenge and concurrent confirmations are rejected. Only
owner can revoke/renew; renewal cannot resurrect a revoked grant. Replacement
changes grant ID even for the same publisher UID. Lease expiry blocks stage and
activation. No Keychain dependency is required for synthetic tokens.

Activation reads grant, pointer, manifest and every referenced object/bucket in
one Firestore transaction, validates the usual shared wire contract and hashes,
then commits CAS and `previousGeneration`. Interrupted staging never advances the
pointer. Immutable records make retries safe; equal root fingerprints write
nothing; one changed entity writes an object, bucket, manifest and pointer.
Receipts contain no payloads or tokens. Explicit owner GC collects unreachable
data in bounded batches, protects current/previous, and is never called on the
publication path. Concurrent deletion invalidates activation transaction reads.
An interrupted stage can therefore be collected and must be staged again.

## Web and isolation

The sole development URL is
`http://127.0.0.1:15173/miagenda/?mirrorEmulator=1`. Development mode, exact
localhost hostname and explicit URL opt-in are all required. The project, ports
and synthetic account are fixed in a dev-only module; no variable can redirect
this mode to production. It uses MirrorRuntime → shared Firestore Lite HTTP transport →
LocalMirrorSession → MirrorReader → IndexedDBMirrorCache → MirrorApp. No Online
selector, editable SyncEngine or outbox is constructed. Auth Emulator owner uses
`owner@example.test` and an explicitly synthetic credential; the E2E provisions
it. Reload offline restores authenticated local state and validated generations.

The local authority refuses missing opt-in, altered emulator endpoints, real
credential variables or a different GCLOUD_PROJECT before creating clients. A
new in-memory synthetic RSA certificate avoids ADC and metadata discovery. The
Swift HTTP executable requires an unsigned token for the demo project and posts
only to a fixed loopback URL. Neither executable is an Xcode application target.
Firestore Lite avoids WebChannel connectivity probes to Google when a connection fails;
the E2E blocks external HTTPS attempts and requires zero external page requests.
Normal `npm run check` includes a built-artifact scan proving emulator modules,
config, credentials and synthetic payloads are absent from `dist`.

## Limits before technical RC

This is a real Firebase emulator integration with a local trusted validator;
it is not a deployable production backend. Production needs the equivalent
trusted pairing/validator authority, production rules reviewed against the same
matrix, real auth/publisher credential lifecycle, configured endpoints and smoke
validation. These are deliberately not provisioned or deployed here. Physical
Apple permission, EventKit occurrence/cancellation semantics, notifications and
actual iCloud coordination remain independently pending. The synthetic provider
cannot certify those behaviors.
